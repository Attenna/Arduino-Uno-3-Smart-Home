# A 板红外接收恢复（Issue #142）

日期：2026-11-17。状态：任务分支真机通过，待独立审阅合并。

## 问题与定位

现场遥控器不能触发自动化规则。A 板串口和环境传感器在线，网关没有新增有效红外事件。
独立诊断程序沿用旧版抓码器的 `IrReceiver.begin(D3, DISABLE_LED_FEEDBACK)`，
确认 D3 有输入且能解码。用户最后按“1”时收到地址 0、命令 69（0x45）。
中途出现其他按键码，不能将第一组 0x44 认定为“1”。

首次固定 70 秒采集未观察到跳变；后续持续采集成功，首次结果不能用于认定硬件故障。
恢复原生产固件后用户重按“1”，网关仍无新事件。替换生产固件的初始化方式后，
相同硬件、规则和网关收到有效事件并成功执行动作。证据将问题定位到原生产接收实现；
没有单独测定全局构造阶段内部状态被改变的具体时刻。

## 修改

- 生产固件使用库的默认接收实例，并在 `setup` 调用路径中显式初始化 D3。
- 禁止 D13 接收反馈灯，避免占用 RC522 的 SPI SCK。
- 未知协议、溢出和长按重复帧不生成按键事件；同键防抖，不屏蔽快速切换不同键。
- 固件版本 `V2.4-IR`。保留 A0 灯带、A1 风扇单线输出和原串口协议。
- 新增临时独立诊断工具，不能用它代替生产固件长期运行。

## 验证

- PlatformIO Uno 完整固件编译成功（RAM 1106/2048，Flash 24034/32256 字节）。
- 独立诊断工具编译成功（RAM 504，Flash 9200 字节），IRremote 4.7.1 与生产相同。
- 每次烧录前备份运行时、记录香橙派 main、读取 A 板 Flash；临时诊断结束恢复原 Flash，
  32768 字节回读校验通过。修复固件烧录也经过回读校验，启动上报 `V2.4-IR`。
- 分支测试时 main/正式运行时标记保持 `4dde9435da9c4ef777f6d162465e3b9fad787466`。
- 北京时间 19:05–19:06：入库事件 protocol=7、address=0、command=69；
  “红外键1：灯开/关切换”规则开/关均 success=1；语音唤醒规则也成功。
- 用户确认短按切换和按住五秒仅切换一次均正确，实体灯行为符合预期。
- 未修改 PC_Test 服务，不重复运行 Python 服务全量测试。

“1”同时关联现有灯光切换和免唤醒语音两条规则，保持用户配置。
本次不包含历史分支中的 B 板红外发射位序修复，不代表空调/红外发射链路也已验收。
