# 红外遥控按键方案

A 板 D3 接收 NEC 按键，经网关交给自动化引擎执行。`V2.4-IR` 已过滤长按重复帧。
固件不内置业务动作，规则不需要重烧 Arduino。

## 0–9 精简方案（显式安装）

| 按键 | NEC command | 动作 |
|---|---|---|
| 1 | 0x45 | 灯开/关切换，沿用当前亮法 |
| 2 | 0x46 | 风扇手动开/关切换；进入持续手动控制 |
| 3 | 0x47 | 门开/关切换 |
| 4 | 0x44 | 窗开/关切换 |
| 5 | 0x40 | 恢复26°C自动温控 |
| 6 | 0x43 | 蜂鸣器短响一次（100毫秒） |
| 7 | 0x07 | 白光25% |
| 8 | 0x15 | 白光60% |
| 9 | 0x09 | 白光100% |
| 0 | 0x19 | 关灯 |

每个按键只有一条规则，冷却1秒。无语音唤醒功能，也不调用语音服务。
按键码沿用此遥控器的 NEC 表；1已实测0x45，其他新增键需逐一在现场核对。
A 板风扇硬件只有开/关，开启请求为100%，不做PWM调速。

## 风扇控制与优先级

此前按2开风扇后，未让位的26°C规则每2秒检查一次，低温立即关扇，
表现为转起来又慢下来。当前方案按2时同时将 `g:允许自动开风扇` 设为false，
温控开/关两条规则都检查这个许可。因此按一次2持续转，再按一次2关闭，
即使原有30秒手动标志到期也不会被温控抢回。

按5将许可恢复为true并解除风扇的短期手动标志，最迟下一轮温控检查
（约2秒）按实测温度执行：高于26°C开，不高于26°C关；数据陈旧时不执行。
这是2026-11-17用户最新要求，取代此前风扇遥控30秒后自动恢复的方案。
灯光仍是手动操作优先30秒，然后恢复光敏控制。

门禁延时关门和原有窗安全策略保留：雨水/烟雾未明确解除、传感器陈旧时不自动开窗。
本方案不改变门窗固件、OLED禁屏和红外发射/空调码。

## 安装与去重

默认预设仍为1–4。本方案在用户明确选择后安装，不会在服务升级时自动删除自建规则。
配置文件为 `PC_Test/examples/automation/ir-remote-0-9.json`，温控模板为
`PC_Test/examples/automation/fan-temperature-26.json`。

先备份运行时、规则JSON、全局状态、部署标记，并记录香橙派仓库main提交。
停止Web网关后，从任务分支生成独立配置文件：

```bash
python PC_Test/scripts/configure_ir_remote.py --input /path/automation_rules.json --output /tmp/remote-rules-new.json
```

工具不覆盖输入文件；输出文件已存在也拒绝覆盖。审阅替换名单及按键表后，
在网关停止期间原子替换运行时规则文件，再启动原Web容器。
全部旧IR接收规则被0–9方案取代，包括同键语音唤醒、旧英文开/关灯规则，
避免同一按键同时执行多项不同目的动作。非遥控规则保留，只给temp26on/off补充自动许可。
检测到其他启用的自动风扇动作会拒绝生成，防止隐蔽的抢占；需先审阅并处理冲突。
配置生成可重复执行，已有1–4预设ID保留，不累积规则。

回滚：停Web，恢复备份的规则及全局状态文件，再启动原Web。无需回烧固件。
部署和合并仍遵循仓库独立分支真机测试及人工审阅流程。

## 验收

1. 按2，温度低于26°C也持续转动超过30秒，再按2停止并保持停止。
2. 按5，观察温控恢复；升至26°C以上开启，降到26°C时关闭。
3. 按6只短响一次；7/8/9依次显示低/中/高白光；0关灯。
4. 按1只切换灯，不再请求语音；灯手动优先期后恢复光敏联动。
5. 每个按键事件只匹配一条IR规则；重复重启后不恢复已删除的重复规则。
