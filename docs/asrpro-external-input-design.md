# ASRPRO 外部串口输入接口设计（评审稿）

> 状态：待确认，当前文档不改变运行行为，也不包含具体场景实现。

## 1. 目标与边界

本接口把 ASRPRO 识别出的语音意图交给香橙派处理，再由香橙派调用现有的、受认证的
Web 硬件网关控制实体设备。它是“输入适配层”，不代替场景引擎，也不直接操作 A/B 板。

设计目标：

- 后续增加命令时，不必重写串口读取、应答、超时和错误处理；
- 旧版 `SH1` 1–9 号命令继续可用；
- ASRPRO 只能调用香橙派显式注册的意图，不能透传任意工具名、URL 或 Arduino 原始帧；
- 每次物理动作都有请求编号和明确结果，超时后不自动重试；
- 单元测试使用模拟网关，不打开真实串口、不驱动真实设备。

暂不实现：天气联网、地理位置配置、穿衣建议、超声波触发规则、车库门场景和动态 TTS。

## 2. 推荐架构

```text
ASRPRO 关键词/离线识别
        │  SH2 意图帧
        ▼
asrpro_bridge 串口适配器
  ├─ 帧解析与长度限制
  ├─ 意图注册表（白名单）
  ├─ 参数 schema 校验
  ├─ 请求去重与超时控制
  └─ 统一结果映射
        │  Bearer Token + HTTP
        ▼
Web /api/hardware/tool 或只读状态 API
        │
        ▼
现有 A/B 板串口独占进程 → 实体设备
```

具体场景以后注册为“意图处理器”，而不是塞进串口循环。天气查询、传感器判断、设备动作、
播报内容等由处理器编排，底层传输代码保持不变。

## 3. 串口协议提案

### 3.1 传输约定

- UART：115200、8N1、ASCII、每帧以 `\n` 结束，兼容 `\r\n`；
- 一次只允许一个请求在途；
- 请求编号为 `1..999999999`，用于匹配应答与去重；
- 单帧最多 127 字节；超长、乱码、未知版本整帧丢弃，不触发设备；
- 字段以一个空格分隔，意图名和参数只允许下述字符集，避免引入通用 JSON 解析器。

### 3.2 请求帧

```text
SH2 <请求编号> <意图名> [<参数名>=<参数值> ...]
```

约束：

- 意图名：`[a-z][a-z0-9_]{0,31}`；
- 参数名：`[a-z][a-z0-9_]{0,15}`；
- 参数值：注册处理器声明的整数、枚举或布尔值；不接受自由文本；
- 参数顺序不影响语义，重复参数、未知参数或缺少必填参数均拒绝。

预留示例（仅说明格式，不代表本次实现这些场景）：

```text
SH2 104 leave_home
SH2 105 garage_open reason=drive_out
SH2 106 light_set mode=white level=255
```

不允许：

```text
SH2 107 call_url url=...
SH2 108 raw_serial data=...
SH2 109 hardware_tool name=door action=open
```

### 3.3 应答帧

```text
SH2 <请求编号> <意图名> <结果码> [<参数名>=<参数值> ...]
```

结果码：

| 结果码 | 含义 | ASRPRO 建议行为 |
|---|---|---|
| `OK` | 意图处理成功 | 播放对应成功音频 |
| `REJECTED` | 意图或参数不在白名单 | 播放“暂时无法执行” |
| `BUSY` | 上一请求尚未结束 | 播放“请稍后再试” |
| `FAILED` | 网关明确返回失败 | 不播报成功 |
| `TIMEOUT` | 结果未知，可能已动作 | 提示未确认，禁止自动重发 |

示例：

```text
SH2 104 leave_home OK speech=301
SH2 105 garage_open FAILED speech=390
```

`speech` 是预先烧录的音频资源 ID，不是自由文本 TTS。需要动态天气播报时，应另行设计受限的
结构化字段或由香橙派音频服务播放，不能把任意网络文本直接交给执行器协议。

## 4. 香橙派处理接口

桥接服务建议新增以下内部抽象；这些是 Python 内部接口，不直接暴露到网络：

```python
@dataclass(frozen=True)
class IntentRequest:
    request_id: int
    intent: str
    arguments: Mapping[str, str]

@dataclass(frozen=True)
class IntentResult:
    code: Literal["OK", "REJECTED", "BUSY", "FAILED", "TIMEOUT"]
    response: Mapping[str, int | str] = field(default_factory=dict)

class IntentHandler(Protocol):
    def __call__(self, request: IntentRequest, context: "IntentContext") -> IntentResult: ...

class IntentRegistry:
    def register(self, name: str, schema: "ArgumentSchema", handler: IntentHandler) -> None: ...
    def dispatch(self, request: IntentRequest, context: "IntentContext") -> IntentResult: ...
```

`IntentContext` 只提供经过封装的能力：

- `hardware.call(name, arguments, timeout)`：调用现有 `/api/hardware/tool`；
- `status.read()`：读取允许的状态字段；
- 后续可选 `weather.read(configured_location)` 和 `speech.play(...)`。

处理器拿不到服务令牌、串口对象或任意 HTTP 客户端。注册表启动后冻结，运行时不能通过串口
添加新意图。第一版建议把注册表写在代码中；若以后改为配置文件，配置仍须做严格 schema
校验，并且不得包含凭据。

## 5. 兼容与迁移

1. 保留现有 `SH1 <请求号> <命令ID>` 和对应响应，已有 1–9 号模型无需重新烧录；
2. 新固件优先使用 `SH2`；桥接服务按版本选择解析器；
3. 同一物理动作在 `SH1` 与 `SH2` 中共享同一个安全调用封装；
4. 旧桥接服务收到 `SH2` 会丢弃，不会误执行；新桥接服务收到未知意图会返回 `REJECTED`；
5. 协议稳定后，再为每个场景分配意图名和音频资源 ID。

## 6. 安全与可靠性要求

- 执行动作必须经过现有 Web 服务鉴权、工具 schema 和审计记录；
- 串口设备路径必须固定到 ASRPRO 的 `/dev/serial/by-id/` 或 `/dev/serial/by-path/`，不得占用
  A/B 板端口；
- 动作调用不自动重试；请求超时表示“结果未知”，不能等同失败后再次开门；
- 在一个短时窗口内缓存 `(请求编号, 意图名)` 的最终结果，重复帧只返回缓存结果；请求编号相同
  但内容不同则拒绝；
- 串口日志只记录版本、请求编号、意图名、结果码和耗时，不记录令牌、自由文本或完整 HTTP 响应；
- 场景涉及开门、车库门等高影响动作时，应单独设置允许条件、冷却时间和传感器校验；
- 超声波“检测到车”不能只靠单次距离值，应使用连续样本、阈值回差和冷却时间，且默认只播报，
  自动开门需另行明确授权。

## 7. 测试契约

实现阶段至少覆盖：

- 合法帧、分段帧、粘包、`\r\n`、超长帧和非 ASCII 输入；
- 未知版本、未知意图、重复/未知/缺失参数；
- 注册表冻结与重复注册；
- 请求重复、请求编号冲突、忙状态；
- 网关成功、明确失败、异常和超时；
- 超时后绝不自动重发实体动作；
- `SH1` 1–9 回归兼容；
- 全部测试使用 fake gateway，不连接真实串口。

## 8. 场景设计建议（待接口确认后另开实现）

### 8.1 “我出门了”

建议流程：获取配置地点天气 → 生成受控建议 → 播报 → 可选执行离家场景。网络失败时仍应给出
基础道别，不应阻塞门、灯等本地动作。

建议话术：

- 晴天温和：“海淀区今天天气不错，气温约二十二度，穿一件薄外套就好。祝您一路顺风，
  我在家等您回来。”
- 降雨：“海淀区今天有雨，出门记得带伞，路上慢一点。祝您一路顺风，我会照看好家里。”
- 寒冷：“室外温度较低，建议加一件保暖外套。注意保暖，平安回来。”
- 天气不可用：“暂时没查到室外天气，出门前记得看看窗外。祝您一路顺风，我在家等您回来。”

### 8.2 车辆靠近车库

建议默认只播报并等待确认：“检测到车辆靠近，需要我打开车库门吗？”只有在身份/区域、连续测距、
车库门状态和防夹条件都满足后，才可升级为自动开门。若以后明确允许自动开门，播报可用：
“检测到您的车辆，正在为您打开车库门，请慢行。”

### 8.3 “我要开车出去”

建议流程：检查门状态和安全条件 → 发出一次开门动作 → 收到明确确认后播报。推荐话术：
“车库门正在打开，路上注意安全，祝您一路顺风。”若结果未知则说：
“车库门状态暂时没有确认，请先观察后再通行。”

## 9. 确认项

进入实现前需要确认：

1. 是否采用兼容 `SH1` 的 `SH2` 文本协议；
2. 是否接受“意图白名单”，而不是允许串口直接指定任意硬件工具；
3. 动态播报由 ASRPRO 预录音频组合，还是后续增加香橙派 TTS；
4. 车辆靠近场景默认“询问后开门”还是明确授权“自动开门”；
5. 第一批要注册的通用意图范围（建议先只做灯、门、窗、风扇和只读状态）。
