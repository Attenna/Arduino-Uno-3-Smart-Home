# 硬件能力清理与当前联动逻辑

移除空调 HTTP 与 MCP 工具、前端控制入口、自动化能力。土壤湿度从页面和当前状态接口移除，历史 SQLite 列保留。风扇只开关，旧正转速指令归一到 100、零值为关闭。移除 `/voice` 页面、模板与脚本，其他语音后台联动沿用原实现。

家庭设置通过 `/api/access/persons` 读取门禁同一份人员数据，凭证与启停统一在门禁页面管理。浏览器旧示例成员不自动迁入授权名单，防止凭空授予门禁权限。家庭角色不是管理员权限，后续若需要 owner/member/guest，应关联稳定的人员 ID 并独立维护权限。

通知配置原先只写 localStorage，没有 Notification API、权限申请、事件订阅或后台推送。现将未接入选项禁用并明确说明。门禁页现有通过/拒绝提示是网页内 Toast，不受这些占位偏好控制。

摄像头采集服务持续出帧。人脸识别哨兵根据 PIR 门控决定是否取帧识别；本机测试关闭门控，每 2 秒轮询。部署默认 motion_hold=20 秒，超过 120 秒未收到 PIR 数据时退化为持续检测，门控不直接关闭摄像头。

拍照取证由自动化的 camera 动作、密码连续失败至少 3 次，或预留的门口停留监测触发。自动化以独立超声波 distance_cm 为输入，数值须在 2–400 厘米内且 3 秒内有效；阈值与 hold_sec 由规则定义。当前本机没有距离拍照规则。

预留 SecurityMonitor 门口停留监测默认 disabled，distance_cm=100、hold_sec=30、max_gap_sec=5。它读取独立的 doorway_distance_cm 字段，不能直接假定已有 B 板 distance 通道会触发这一预留路径。启用前应接线并明确使用自动化距离规则或完成此路径接入。

室内 PIR 同时用于有人/无人自动化与识别节流；不能代替门口测距。默认无人 120 秒的规则与人脸识别保持 20 秒属于不同策略。

本机验证：Python 347 项通过；JavaScript 26 项中 25 项通过，历史页光照字段静态断言为已复现的既有失败。页面及删除路由核查通过，原两名人员、人脸特征、模型与摄像头状态正常。
