## 2. 各坑详解

### 2.1 供电不足 → 反复重启

**现象**：烧录 `avrdude done` 成功，监视器却无输出，或每隔几秒刷一条 `ready`（`setup()` 反复执行）。

**根因**：NeoPixel(8颗) + 2×SG90 + 风扇等外设全从 Uno 的 5V 取电，峰值超 1A。5V 被拉到约 4.5V 以下时，ATmega328P 触发欠压复位（BOD）。

**判断**：
- 监视器刷出**多条** `ready`（反复重启）而非零条；
- 板载 ON 电源灯变暗/闪烁；
- 万用表测 5V 引脚 < 4.8V。

**解法**（治本）：
- 舵机红线、灯带 5V、L298N VCC 接**独立 5V/2A 电源**；
- 独立电源 **GND 与 Uno GND 共地**；
- Uno 本体继续 USB 供电（通信用）。

### 2.2 LED 上电默认亮 → 欠压复位

**现象**：把灯带改成上电默认亮后，板子开始反复重启。

**根因**：8 颗 NeoPixel 在亮度 60 时约多 113mA 常驻电流，把本就吃紧的 5V 再压低，触发 BOD。

**解法**：`Config.h` 新增配置开关 `LIGHT_BOOT_ON`（默认 `0` 熄灭）、`LIGHT_BOOT_LEVEL`（默认 `20`）。
确需上电亮灯，必须先解决独立供电。

### 2.3 OLED 是 SPI 却按 I2C 驱动

**现象**：OLED 半死不活，且 OLED 刷新命令会「搅乱」旁边 D4 的灯带。

**根因**：这块屏是 **SPI 4 线接口**（5 根线：SCK/SDA/RES/DC/CS），不是 I2C（2 根线 SDA/SCL）。
固件之前用 I2C 时序去敲 A4/A5，而实物 SCK 在 D13、SDA 在 D11——接口类型都错了。
I2C 时序在错误引脚上的乱翻信号窜进邻近的 D4（灯带数据线），导致灯带花屏。

**解法**：驱动改为 `U8X8_SH1106_128X64_NONAME_4W_HW_SPI`，引脚如下：

| OLED 线 | Uno 引脚 | Config.h 宏 |
|---------|----------|-------------|
| SCK | D13 | 硬件 SPI 固定 |
| SDA(=MOSI) | D11 | 硬件 SPI 固定 |
| RES | A1(=D15) | `OLED_RES_PIN` |
| DC | A0(=D14) | `OLED_DC_PIN` |
| CS | D10 | `OLED_CS_PIN` |

**如何区分屏是 I2C 还是 SPI**：看引脚数——I2C 屏只有 4 根（VCC/GND/SCL/SDA）；SPI 屏有 7 根（VCC/GND/SCK/SDA/RES/DC/CS）。

### 2.4 型号 SH1106 vs SSD1306

**现象**：接线正确但白屏 / 显示错乱 / 有残影。

**根因**：SH1106 与 SSD1306 驱动时序不同，屏型号不匹配。

**解法**：改 `Config.h` 的 `OLED_IS_SH1106`（`1`=SH1106，`0`=SSD1306）后重烧。
大多数 0.96 寸 128x64 SPI 屏是 SSD1306，部分蓝黄双色屏是 SH1106。

### 2.5 全角引号导致 parse_error

**现象**：手打命令正常，从聊天软件/文档复制的命令报 `parse_error`。

**根因**：复制时引号 `"` 被转成全角 `“”`、冒号变 `：`、逗号变 `，`，`deserializeJson` 解析失败。

**解法**：固件 `Protocol::normalizeFullWidth()` 在解析前自动把全角转半角，从哪复制都不再报错。

### 2.6 `_pos` 清零顺序 bug（串口全挂）

**现象**：加了全角兼容后，**所有**串口命令都报 `parse_error`。

**根因**：`handleSerial()` 里 `_pos = 0` 写在 `normalizeFullWidth()` **之前**，
导致归一化函数看到的行长度是 0，命令缓冲被清成空字符串。

**解法**：顺序改为**先 `normalizeFullWidth()`、再 `_pos = 0`**：

```cpp
if (_pos > 0) {
    _buf[_pos] = '\0';
    normalizeFullWidth();  // 内部重算 _pos
    _pos = 0;
    handleLine(_buf);
}
```

## 3. 排障速查顺序（Module B 无响应时）

1. **看监视器有没有 `ready`**：一条 → 正常；多条 → 欠压复位（查供电）；零条 → 查端口/波特率/烧录。
2. **量 5V 电压**：外设全接时 < 4.8V 就是供电不足。
3. **换 USB 线 / USB 口**：细线压降大，上传时电流小能过、运行时电流大就复位。
4. **拔掉大功耗外设**（舵机/灯带）：恢复即实锤供电问题。
5. **确认命令是半角**：现固件已自动兼容，一般无需担心。

## 4. 关键设计原则（始终遵守）

- Module B **只执行、不判断**，业务逻辑全在 HA；
- 驱动之间**禁止互相调用**（如 Door→OLED、Light→Buzzer）；
- 引脚/角度/时间参数**集中在 `Config.h`**，驱动内不硬编码；
- 串口命令**兼容 JSON 与冒号两种格式**，且**不区分大小写、自动全角转半角**。
